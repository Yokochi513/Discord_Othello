# M3-10: 2 人での通し対局の疎通確認（手順書）

Issue #39 の作業手順。要件定義.md §12 応答性 / §14 異常系 / §17 テスト方針 / §18 マイルストーン M3
に対応する。

この Issue の中心作業は、**ラズパイ上の本番環境で Discord クライアントを複数使って行う手動確認**
であり、リポジトリへのコード変更だけでは完了できない。本書はその手動作業の手順・判定基準・
記録欄をまとめたものである。

あわせて、**画面操作では再現できない異常系 E-01〜E-05 を本番サーバーに対して再現するための
プローブ**を追加した（`packages/server/src/probe.ts`）。対局画面は「自分の手番の合法手」しか
押せないため、E-01〜E-05 は画面からは送れない。要件定義 §15 が求める「クライアントからの入力は
一切信用しない」ことを本番で確かめるには、改変クライアント相当の生のメッセージが要る。

---

## 1. 前提条件

- M3-1〜M3-9（Issue #30〜#38）がマージ済みであること
- M2-5 の手順でラズパイへのデプロイと Cloudflare Tunnel の常駐が済んでいること
  （`docs/m2-5-cloudflare-tunnel.md`。`othello.service` / `cloudflared-othello.service`）
- Discord アカウントが 3 つ使えること（黒番・白番・観戦者）。同一ボイスチャンネルに入れること
- プローブを実行する機械に Node.js 22 以上があること（開発機でもラズパイでもよい）

観戦者用の 3 人目が用意できない場合は、§3.8 と E-03 の確認だけ実施できない。その旨を §6 に記録する。


## 4. 応答性の確認（要件定義 §12: 着手から盤面更新まで 1 秒以内）

2 通りで確かめ、両方の結果を §6 に記録する。

### 4.1 目視（本命）

2 台の画面を並べる、または画面録画を撮り、片方が石を置いてからもう片方の盤面が変わるまでが
**体感で 1 秒以内**であることを確認する。録画した場合はフレーム数から概算する。

### 4.2 プローブによる実測（補助）

`measure` は、対局者のトークンで 2 本接続し、**実際に 1 手打って**別接続へ盤面更新が届くまでを
測る。ネットワークとサーバーの往復だけを測るため、画面描画は含まない。

```bash
node packages/server/dist/probe.js measure \
  --url wss://othello.<所有ドメイン>/ws \
  --instance <instance_id> --token <access_token> --repeat 3
```

- 自分の手番になるまで待ち、合法手を 1 つ選んで打つ。**対局の手が本当に進む**ので、
  §3 の通し対局のなかで、打ち手の合意のうえで実行すること
- `--repeat` の回数だけ、相手の着手を待って繰り返す
- 出力例:

```
[合格] 1 回目: 着手 d3 から別接続の盤面更新まで 2 ミリ秒（上限 1000 ミリ秒）

結果: 3 回計測 / 最大 2 ミリ秒 / 平均 1 ミリ秒
```

- 1 回でも上限を超えると終了コード 1 で終わる

## 5. 異常系 E-01〜E-05 の再現（要件定義 §14 / §17）

### 5.1 接続情報の取り出し方

プローブには、Activity と同じ **access_token** と **instance_id** が要る。Discord クライアントで
Activity を開き、開発者ツールの Network から `/.proxy/ws?...` の接続 URL を見ると、
`access_token` と `instance_id` の両方がクエリに載っている（`packages/client/src/api.ts` の
`resolveWebSocketUrl`）。この 2 つを控える。

- `instance_id` だけならサーバーログにも出る（`WebSocket 接続: userId=... instanceId=...`）
- **access_token は短命の秘密情報である。** 記録・共有・コミットのいずれもしないこと（§15）
- プローブの接続先は Discord のプロキシではなく、公開しているホスト名を直接指定する
  （`wss://othello.<所有ドメイン>/ws`）

### 5.2 実行方法

ラズパイ上（ビルド済み）なら:

```bash
node /opt/Discord_Othello/packages/server/dist/probe.js check \
  --url wss://othello.<所有ドメイン>/ws \
  --instance <instance_id> --token <access_token>
```

開発機からソースのまま実行する場合は `npm run probe --workspace packages/server -- check ...`。
環境変数 `OTHELLO_PROBE_URL` / `OTHELLO_PROBE_INSTANCE` / `OTHELLO_PROBE_TOKEN` でも渡せる。

### 5.3 実行するタイミングと、再現できる異常系

プローブは接続直後のルーム状態から**いま再現できる異常系だけ**を実行し、残りは理由を添えて
「未実施」と表示する。次の 4 回に分けて実行すると E-01〜E-05 がすべて埋まる。

| 実行するタイミング   | 使うトークン         | 再現される異常系 |
| -------------------- | -------------------- | ---------------- |
| 対局中               | 手番でない側の対局者 | E-01 / E-05      |
| 対局中               | 手番側の対局者       | E-02 / E-05      |
| 対局中               | 観戦者               | E-03 / E-05      |
| 終局後、再戦を押す前 | どちらでも           | E-04 / E-05      |

- 中断（§3.7）で終えた対局は破棄されるため、**E-04 は投了か自然終局のあとに確認する**
- 実行中は他の人が着手しないこと。着手と重なると「拒否と同時に配信が起きた」と判定される

### 5.4 期待する結果

```
利用者: 1234567890（white 番）
対局: 0f2a... 手数 4 手番 black（黒 3 / 白 3）

[合格] E-01 手番でない者が着手した: invalid_state「手番ではありません」で拒否され、配信は起きなかった
  送信: {"type":"move","gameId":"0f2a...","square":"d3"}
[合格] E-05 存在しない対局 ID の指定: game_not_found「対局が見つかりません」で拒否され、配信は起きなかった
  送信: {"type":"move","gameId":"00000000-0000-0000-0000-000000000000","square":"d3"}
[未実施] E-02 非合法手が送られた: このトークンの利用者が手番でない（手番側のトークンで実行する）
...
[合格] 盤面は実行前と同じ（拒否によって盤面は壊れていない）

結果: 実施 2 件 / 不合格 0 件 / 未実施 3 件
```

判定:

| 異常系 | 期待するエラー種別 | 要件定義 §14 の扱い          |
| ------ | ------------------ | ---------------------------- |
| E-01   | `invalid_state`    | 拒否し、盤面は変えない       |
| E-02   | `illegal_move`     | サーバー側で検証して拒否する |
| E-03   | `unauthorized`     | 拒否する                     |
| E-04   | `invalid_state`    | 拒否し、終局画面へ誘導する   |
| E-05   | `game_not_found`   | ロビーへ戻す                 |

加えて、いずれの拒否でも**盤面が配信されないこと**と、**実行の前後で盤面が同じであること**を
プローブが自動で確かめる。1 件でも不合格なら終了コード 1 で終わる。

画面側の挙動（E-04 で終局画面に留まる、E-05 でロビーへ戻る）は、対局者の Discord 画面が
崩れていないことを目視で併せて確認する。

### 5.5 注意

- **対局者のトークンで実行するときは、その人の Discord クライアントを開いたままにすること。**
  そのユーザーの接続がすべて閉じると、E-09 により対局が無効試合として終わる
- プローブが接続・切断するたびに参加者一覧が配り直される。観戦者が一瞬増減して見えるのは正常

## 8. 申し送り

- E-06〜E-15（切断・再接続・サーバー再起動）は M3 の範囲外。M5（Issue の後続）で扱う
- プローブは診断用のため、`packages/server` のビルド成果物に含まれる（`dist/probe.js`）。
  サーバーの起動経路（`dist/index.js`）からは参照しない
- プローブが再現するのは E-01〜E-05 に限る。他の異常系を足す場合は
  `packages/server/src/probePlan.ts` の `planChecks` に検査を追加する
  （純粋な組み立てのため `probePlan.test.ts` で検証できる）
